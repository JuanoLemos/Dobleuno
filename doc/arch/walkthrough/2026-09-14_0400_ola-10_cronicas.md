## Qué se hizo

Una partida de TOW dejaba un `BattleState` con unidades, bajas, turnos y log, y eso moría en la
base. Crónicas lo convierte en un relato generado con DeepSeek más una galería de fotos de la
mesa, con visibilidad privada o publicada al club.

La ola arrancó con una fase 0 no planeada como feature: `/api/battles` y `/api/lists` no tenían
auth, y `endBattle()` no persistía. Sin eso, Crónicas no podía preguntar "¿esta batalla es tuya?"
ni tener batallas terminadas de dónde partir.

## Decisiones

| Decisión | Fundamento |
|---|---|
| Tablas propias, no `battles.data` | El PATCH del tracker reescribe el jsonb entero: si el jugador tiene la batalla abierta mientras sube fotos (el caso normal — las fotos se sacan *durante* la partida), el PATCH pisa el array. Además la galería quedaría sin índice |
| El arreglo de auth entra en esta ola, no en un release aparte | Lo ofrecí como `v1.0.4` previo; el usuario prefirió un solo release. El diff mezcla fix de seguridad con feature, pero el changelog los separa |
| Visibilidad elegida por el autor, default privada | Publicar es una acción deliberada. La alternativa "todo el club ve todo" obligaba a decidir moderación, que MODULES.md ya había descartado para el MVP |
| Anclas `[u:N]`/`[h:N]` validadas en el server | Es el mismo principio que las citas del oráculo. Diferencia: acá los marcadores inválidos se **borran del texto**, porque un `[u:9]` colgado en un relato que alguien va a compartir no es ruido tolerable |
| Downscale en el cliente, no `sharp` en el server | Evita meter libvips en alpine y la foto sale del celular pesando cientos de KB en vez de 4 MB — importa porque se saca en la mesa con datos móviles |
| Capability URLs para las fotos | Un endpoint autenticado rompe en dev: sin proxy en Vite, un `<img src>` cross-origin no manda cookies. Es el mismo modelo que una presigned URL de S3, que es adonde esto migra |
| Volumen `dobleuno-uploads` separado de `dobleuno-kbdata` | La KB es cache regenerable, las fotos no. Compartir volumen garantiza que alguien lo borre para forzar un re-sync y se lleve las fotos del club |
| Naming en español | `doc/MODULES.md` había escrito la spec en inglés (`Chronicles.tsx`), pero Ola 9 sentó el precedente contrario. Se corrigió la spec |

## Lo que no se pudo verificar

- **`npm run db:migrate` contra Postgres real**: no hay Docker en esta máquina. La migración está
  generada y leída a ojo; el CI la aplica.
- **Los permisos del volumen en Docker**, que era el riesgo #1 del plan. El `mkdir` + `chown`
  antes del `USER` está puesto según el modo en que Docker inicializa un volumen nombrado, pero
  no se probó en un contenedor.
- **La calidad del relato con DeepSeek real**: todo el pipeline corrió contra el mock. El prompt
  va a necesitar iteraciones cuando se pruebe con la API de verdad.
