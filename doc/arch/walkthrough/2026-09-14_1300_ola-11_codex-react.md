# Walkthrough — Ola 11: Codex en React

**Fecha:** 2026-09-14 13:00 · **Comando:** `/plan` → implementación por fases · **Modelo:** Claude Opus 5

---

## Qué se hizo

El ROADMAP pedía "portear las páginas Astro a React, mantener SEO si es posible". Al relevarlo, la
ola cambió de forma: **no había contenido que portear, el portal nunca se desplegó, y el SEO que
había que mantener no existía.**

Los 39 HTML de `data/raw/rule/empire/` tenían el mismo MD5. Eran el shell de carga de Next.js
(`"isFallback":true`, `"pageProps":{}`, título `Loading...`). Las 39 "reglas" de
`data/processed/special-rules.json` eran ese shell parseado: todas llamadas "Warhammer: The Old
World Online Rules Index", todas con `"No description available."`, todas en la categoría
`equipment`. El pipeline terminaba con exit 0 y nadie abrió el JSON durante dos meses.

Así que la ola fue: conseguir el contenido, ponerle un gate para que el silencio no se repita, y
recién después mudar la UI.

## Decisiones

| Decisión | Fundamento |
|---|---|
| Arreglar el pipeline antes de tocar la UI | Sin contenido el porteo no tiene sentido. Y con contenido el oráculo RAG también deja de estar vacío: es valor independiente |
| Público pero con `noindex` | El análisis legal marca a GW como riesgo latente 🔴. Público e indexado es la configuración más expuesta posible. Se resigna el SEO (ADR-011) |
| Taxonomía en texto libre, sin enums | El esquema asumía 2 facciones, 5 categorías, 8 tipos de regla y 4 rarezas, escrito antes de ver los datos. El corpus tiene 31 ejércitos, 31 secciones y 70 familias de item. Forzar ese mapeo fue lo que hizo que las 39 reglas cayeran todas en `equipment` |
| Statlines como string | El sitio usa `-`, `(+1)` y `2D6`. No entran en un integer |
| El corpus va del server a IndexedDB, no al bundle | Son ~3 MB de texto derivado de GW. Bundlearlo lo mete en el artefacto versionado, que es justo lo que `Sources.md` prohíbe |
| Búsqueda y paginado server-side | El SearchBox del portal escondía nodos del DOM. Con 1796 reglas paginadas, lo buscado casi nunca está en la página |
| Prefijo `codex-` obligatorio | `.scroll-divider`, `.cta-primary`, `.cta-ghost` y `.grain` ya existen en `portal.css` con otra definición, y ese archivo lo usa la Home cream. Importar el CSS del portal tal cual rompe `/` en silencio |
| `data-skin` en el body, no en `:root` | El resto de la app es dark forge y no se tiene que mover cuando el usuario entra al Codex y vuelve |
| El oráculo como panel colapsable, no como tab | Es una affordance del Codex, no un producto aparte. Un quinto tab violaba ADR-007 |
| `name_es`/`description_es` nullable, sin default | `null` = "todavía no se tradujo". Un default con el inglés haría indistinguible eso de "traducido igual al inglés", que es justo lo que el validador marca como error |
| Se muestran "Personajes" y "Tropas", no lord/core/special/rare | El sitio no publica la categoría de lista de ejército. Cuatro de los seis filtros del unit picker filtraban a cero |

## Bugs silenciosos encontrados en el camino

Ninguno estaba en el plan. Todos venían de antes de esta ola.

| Bug | Desde | Síntoma |
|---|---|---|
| El mirror bajaba el shell de carga | Ola 2 | 39 entradas basura, pipeline en verde |
| `/api/rules/search` y `/api/kb/stats` eran 404 | Ola 2 | El router se monta en `/api` y declaraba `/search` y `/stats`. Cero tests tocaban estas rutas |
| El seed nunca pobló las tablas del Codex | Ola 2 | Listas vacías con la base sana |
| `parseRobotsTxt` trataba los patrones como prefijos literales | Ola 2 | Respetaba robots.txt de casualidad |
| Las entradas embebidas se descartaban | Ola 2 | "Great Weapon" sin alcance, fuerza ni penetración. 523 reglas |
| Los párrafos partían las frases en cada link | Ola 2 | `"durante la \nfase de Combate\n, el modelo"` |
| Las reglas especiales de las unidades venían pegadas | Ola 2 | `"Counter ChargeFirst ChargeSwiftstride"`, ~500 unidades |
| `scripts/` no corría en CI | Ola 2 | No es un workspace; `npm test -ws` no lo ve |
| El test del parser no probaba el parser | Ola 2 | Re-implementaba la lógica adentro del test, contra fixtures HTML a mano |

Y uno propio, que el CI encontró: la primera versión de `codex-routes.test.ts` afirmaba
`status !== 404` para las rutas de detalle. Pasaba en local — sin base, todo responde 503 — y
falló en CI, donde hay Postgres migrado y vacío: pedir una regla que no existe devuelve 404 con
toda razón. El status no separa "la ruta no está montada" de "no hay esa fila"; el cuerpo sí
(`{error: 'Not found'}` del fallback vs. `'Rule not found'` del handler). Corregido en `02b8944`.

Los dos últimos explican a los siete primeros.

## Lo que no se pudo verificar

- **El seed contra Postgres.** No hay Docker en esta máquina. El CI sí aplicó las migraciones
  `0005`–`0007` contra Postgres real y pasaron, así que el DROP + CREATE de las tres tablas está
  verificado; lo que no corre es `kb:seed`, porque `data/processed/` está gitignored y en el
  runner no hay corpus (de ahí el `--allow-missing`).
- **El Codex contra datos reales.** Sin base, las rutas devuelven 503 y la UI muestra su estado
  vacío. Lo que se verificó es el camino de error, no el de éxito.
- **La traducción.** El traductor está adaptado al corpus nuevo pero no corrió: son 2547 entradas
  de DeepSeek. El Codex hoy muestra inglés, y `/sobre` lo dice.
- **`scripts/` sigue sin lint.** `eslint.config.mjs` lo ignora entero porque ningún tsconfig lo
  cubre. El pipeline —el código que más silencio produjo en este proyecto— es lo único sin
  chequeo estático. Arreglarlo pide un `tsconfig.scripts.json`; queda anotado.
(El checkpoint visual de la Fase 1 sí se hizo: se levantó el dev server, se recorrieron las cinco
rutas, y se verificó que al volver a `/` el body queda sin `data-skin`, con `rgb(10,10,10)` de
fondo y la Home cream idéntica. De paso apareció que el `<title>` no se restauraba al salir del
Codex — se arregló con un Helmet base en `App.tsx` — y que el aviso de cache decía "sin conexión"
cuando el server estaba caído y el usuario tenía red.)
